# Read-only query-reader transfer diagnosis

18 October2026. The verified1,000-update query pilot has a narrow notebook win,
but every legacy access-phrase group scores0/512 under the original six-token
value-only scoring. Do not restart or extend training from that result alone.

This diagnosis uses ONLY the already-scored legacy development probes and the
immutable step1,000 checkpoint. It does not read reserved original TEST or novel
literal inputs, train, change model files/weights, or touch native256. All global
attention positions and KV behavior are the existing model's public paths.

1. Audit learned query selection and source-sentence signals on ALL3,584 cases
   in seven groups. Recover literal features from the exact source IDs in each
   saved prompt; selection does not depend on the semantic encoder features.
   Record selected complete words, entity/topic correctness, scope, eligibility,
   correct record signal and original saved outputs. Expected names/value positions
   are diagnostic labels only, never inputs to the learned selector.
2. Select the first eight sorted units/group, both questions and both memory
   swaps:224 cases, without success filtering. Generate original value-only
   questions with32-token cap, and separately supply a fixed answer prefix
   `The access phrase for NAME is` with16-token cap. Prefix uses only the public
   question's name and relation; audit all token prefixes against full answers
   and ensure no answer-value characters/tokens are supplied. These are new
   diagnostic conditions, not replacements for the original scored task.
3. Block the old fact code for the first two selected units/group (56 prefix
   cases). Also swap that code with the opposite-side same-question case. Verify
   all remaining prompt tokens are identical; donor replay must match its enabled
   prefix output. Report recipient and donor scores separately.
4. Independently rederive every prefix, source subset/edit, token/text/EOS/strict
   score and sampled public uncached CPU outputs. Bind model/evaluator/helper/
   case/output/checkpoint hashes and all prior comparison guards. No optimizer.

Strict success requires EOS and normalized exact value, allowing only case,
whitespace and final-period differences. Also report first-token accuracy and
whether the gold value appears without any distractor value using whole-word
matching; the latter is descriptive and never factual task success. Report
extended-cap results as instruction-following diagnostics, not a corrected
headline score. Prefix improvement would locate an output/query-context transfer
gap, not establish generic reasoning or final two-epoch parity.

CPU selector and GPU generation may run on separate cores; only one GPU worker.
Freeze new helper/protocol/tests once execution begins. Keep the completed pilot
and its comparison immutable. Advance only from measured failure decomposition.
