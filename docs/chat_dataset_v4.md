# Expanded tool and reasoning corpus

Cleanup (2026-10-12): superseded prepared datasets and downloaded source payloads
were removed at the user's request, freeing14.60GiB. Their metadata, source cards,
tokenizers and all model checkpoints remain. V4 is intact and trains directly;
it does not need the deleted files. Reproduction or resuming older runs requires
redownloading/rebuilding the original data. Cleanup receipt:
`dump/old-dataset-cleanup-20261012.json`. Training sources were left unchanged
while the v4 run was active; continue using explicit `--data` for fresh v4 runs.

`dump/data/unified-chat-v4` extends the immutable v3 corpus. It uses the same
4096-token vocabulary, chat template, assistant-only cross-entropy masks,
512-token active blocks and 32 older encoder vectors. No model or trainer source
changes, new parameters, database implementation, tool execution or training.
The internal data format remains `chat-memory-v3`; `corpus_version` identifies v4.

## Filtering and reproducibility

The extension copies v3 token/mask/dialogue/index files as an unchanged prefix,
then seeds its exact-dialogue, prompt-group and cross-split long-answer dedup
indexes from every existing row. Shared prompts keep their previous split.
Source receipts and every base file are hash-checked before copying. No old
training run or original checkpoint is rewritten.

The new adapter accepts schemas embedded within instructional text and JSON-lines
schema lists. It preserves surrounding instructions and reasoning. Plain tool
observations are associated only with a single outstanding call; ambiguous
observations, undefined calls, missing required arguments and mismatched result
names remain rejected. Calls are parsed as data, never executed. Schema checks
do not validate argument types against every JSON Schema rule.

All dialogues must end with an assistant turn. Whole examples exceeding2,560
tokens are excluded, without truncating reasoning, observations or final answers.
Consequently only a subset of long tool/reasoning traces is eligible. There is
no synthetic repair of missing calls or hallucinated tool results. Exact dedup
does not establish semantic independence. Independent benchmark decontamination
remains necessary before claims against external models.

From a fresh checkout, first reproduce v3 using
[the v3 preparation instructions](unified_chat_dataset.md). Then run:

```powershell
python tools/download_chat_extensions.py
python tools/extend_unified_chat.py
python tools/audit_chat_corpus.py --data dump/data/unified-chat-v4
python tools/audit_chat_extensions.py
```

These commands perform only downloading and CPU preprocessing. Existing outputs
are immutable: use `--output` for another build. The saved manifest records all
additions, rejection counts, source identities, final counts and training schedule.

## Fresh training and resumption

After the full audit passes:

```powershell
& D:\Git\latent-text-compressor\.venv\Scripts\python.exe D:\Git\complex_fnn\src\models\token_memory\training.py --name encoder-memory-unified-v4 --data D:\Git\complex_fnn\dump\data\unified-chat-v4 --epochs 2 --batch-size 32 --microbatch 16
```

Resume in the same run folder, restoring its data, optimizer and schedule:

```powershell
& D:\Git\latent-text-compressor\.venv\Scripts\python.exe D:\Git\complex_fnn\src\models\token_memory\training.py --resume D:\Git\complex_fnn\dump\encoder-memory-unified-v4 --microbatch 16
```

An existing v2/v3 run must resume on its original corpus; swapping data during
resume is deliberately refused. The trainer default remains v3 to avoid changing
existing checkpoint source identities. Always specify `--data` for this v4 build.
Micro16 is recommended because the real micro32 run approached the12GB limit.
